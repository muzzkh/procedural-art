Blender 4

Add-ons and Libraries

A script is something you run. An add-on is something you install: your generator becomes a menu entry with sliders, available in every file. This lesson turns scripts into tools, organises reusable code into libraries, and runs Blender without its window to generate in bulk.

From script to tool

An add-on is a Python package that Blender loads at start-up. It registers new pieces of interface with Blender, and they then behave like built-in features. Three kinds of piece cover most add-ons:

Operator
An action: something that appears in a menu or on a button and does a job when run.
Properties
The operator's settings. Blender draws sliders and fields for them automatically.
Panel
A block of interface in a sidebar or properties editor that shows buttons and settings.

The course includes a complete working add-on, blender/addons/procedural_tools, which adds a seeded terrain and a seeded vase to the Add menu. It was run in Blender 5.3: both operators create their objects, the panel registers, and the folder builds into an installable package. The listings below are from it.

An operator

import bpy
from bpy.props import FloatProperty, IntProperty

from . import generators


class MESH_OT_procedural_terrain(bpy.types.Operator):
    """Add a noise terrain generated from a seed"""          # this text is the tooltip
    bl_idname = "mesh.procedural_terrain"                     # how the operator is called from Python
    bl_label = "Procedural Terrain"                           # its name in menus
    bl_options = {"REGISTER", "UNDO"}                         # UNDO also gives the adjust panel after running

    # Properties are declared as annotations. Blender builds the interface for them.
    seed: IntProperty(name="Seed", default=1, min=0)
    size: FloatProperty(name="Size", default=8.0, min=0.1, unit="LENGTH")
    cells: IntProperty(name="Resolution", default=64, min=4, max=512)
    height: FloatProperty(name="Height", default=2.0, min=0.0)
    scale: FloatProperty(name="Feature Scale", default=0.45, min=0.01)

    def execute(self, context):
        vertices, faces = generators.terrain(self.seed, self.size, self.cells, self.height, self.scale)
        build_object(context, f"Terrain {self.seed}", vertices, faces)
        return {"FINISHED"}

What each part does:

  • bl_idname has the form category.name. After registration the operator can be called as bpy.ops.mesh.procedural_terrain(seed=5).
  • The properties use a colon, not an equals sign. Each becomes a control with the limits you give.
  • execute does the work and returns {"FINISHED"}. It receives the context instead of reaching for bpy.context.
  • "UNDO" in the options is what makes the tool feel procedural. After you run the operator, a small panel appears at the bottom left of the viewport (press F9 if it is hidden). Changing a value there undoes and re-runs the operator, so dragging the Seed slider regenerates the terrain live.

A panel and a menu entry

class VIEW3D_PT_procedural_tools(bpy.types.Panel):
    bl_label = "Procedural Tools"
    bl_space_type = "VIEW_3D"               # which editor
    bl_region_type = "UI"                   # its sidebar
    bl_category = "Procedural"              # the tab name

    def draw(self, context):
        layout = self.layout
        layout.label(text="Add from a seed:")
        column = layout.column(align=True)
        column.operator(MESH_OT_procedural_terrain.bl_idname, icon="RNDCURVE")
        column.operator(MESH_OT_procedural_vase.bl_idname, icon="MESH_CYLINDER")


def menu_entries(self, context):
    self.layout.separator()
    self.layout.operator(MESH_OT_procedural_terrain.bl_idname, icon="RNDCURVE")
    self.layout.operator(MESH_OT_procedural_vase.bl_idname, icon="MESH_CYLINDER")

A panel's draw function runs every time the interface redraws, so it must only describe the layout and never change data. The class names follow a convention Blender checks: an upper-case prefix, then _OT_ for operators, _PT_ for panels or _MT_ for menus.

Registration

Blender finds out about your classes only when you register them. Every add-on has these two functions, and unregister must undo everything register did, in reverse order.

classes = (MESH_OT_procedural_terrain, MESH_OT_procedural_vase, VIEW3D_PT_procedural_tools)


def register():
    for cls in classes:
        bpy.utils.register_class(cls)
    bpy.types.VIEW3D_MT_mesh_add.append(menu_entries)       # add our entries to Add > Mesh


def unregister():
    bpy.types.VIEW3D_MT_mesh_add.remove(menu_entries)
    for cls in reversed(classes):
        bpy.utils.unregister_class(cls)

Keep generating separate from interface

Notice the first lines of the operator's execute: it calls generators.terrain(…) and gets back plain lists of points and faces. The file generators.py contains no operators, no panels and no reference to the interface at all.

That separation is the most important structural habit in tool-building:

  • The same function can be called from the add-on, from a stand-alone script, and from a batch job.
  • It can be tested by comparing its output for a known seed.
  • The interface can be redesigned without touching the algorithm.

Packaging and installing

Since Blender 4.2, add-ons are distributed as extensions. An extension is a folder containing your Python files and a manifest, blender_manifest.toml, that describes it:

schema_version = "1.0.0"

id = "procedural_tools"
version = "1.0.0"
name = "Procedural Tools"
tagline = "Seeded procedural meshes from the Procedural Art course"
maintainer = "Your Name"
type = "add-on"

blender_version_min = "4.2.0"

license = ["SPDX:GPL-3.0-or-later"]
tags = ["Add Mesh"]

Blender builds the installable zip for you and checks the manifest as it does so:

blender --command extension build --source-dir blender/addons/procedural_tools --output-dir .

To install: Edit, Preferences, Get Extensions, open the drop-down menu at the top right, choose Install from Disk and pick the zip. For development, it is quicker to point Blender at the folder itself as a local repository, also under Get Extensions, so that edits take effect on restart without rebuilding.

Before 4.2, an add-on was identified by a bl_info dictionary at the top of __init__.py. The course add-on includes one as well, which newer versions ignore.

Libraries

"Library" means three different things in Blender work, and all three are worth setting up.

1. Your own Python modules

Functions you keep rewriting belong in a module. The course's proclib.py is an example: clearing the scene, seeded noise, building an object from lists, a surface from a function, a camera and light. To use a module from a stand-alone script, tell Python where it is:

import sys
sys.path.append(r"C:\path\to\Procedural Art\blender\scripts")
import proclib

proclib.clear_scene()
vase = proclib.grid_surface("Vase", my_function, 96, 60, close_u=True)

Inside an add-on, modules in the same folder are imported relatively: from . import generators. While developing, Blender keeps the old version of a module in memory after you edit it. Either restart Blender or reload it by hand:

import importlib
importlib.reload(proclib)

2. Third-party Python packages

Blender has its own Python, separate from any other on your computer, and it already includes NumPy. For other packages, the supported way in 4.2 and later is to bundle their wheel files inside your extension and list them in the manifest:

wheels = [
  "./wheels/some_package-1.2.3-py3-none-any.whl",
]

Blender installs them when the extension is enabled. Installing packages into Blender's Python by hand with pip also works, but it breaks when Blender is updated and is hard for anyone else to reproduce.

3. Asset libraries

The third kind holds not code but things: node groups, materials, objects and collections that you want to reuse in every project.

  1. In a .blend file, right-click a node group, material or object and choose Mark as Asset. From Python: tree.asset_mark().
  2. Save the file into a folder that is registered as an asset library, in Preferences, File Paths, Asset Libraries.
  3. In any other file, open the Asset Browser and drag the asset in.

A Geometry Nodes scatter system, such as the one from the last lesson's challenge, is an ideal asset: build it once, then drag it onto any object. A script can also pull data out of another .blend file directly:

with bpy.data.libraries.load(r"C:\path\to\library.blend", link=False) as (source, target):
    target.node_groups = [name for name in source.node_groups if name == "Procedural Hills"]

tree = target.node_groups[0]          # now part of this file

With link=True the data stays in the library file and is only referenced, so improving the library updates every project that uses it.

Batch generation

Blender runs without its window when started with --background, which makes it a generator you can script from outside. The course's 04_batch_generate.py produces a rendered image and an STL file for each seed in a list. It was run for two seeds and wrote all four files.

blender --background --python 04_batch_generate.py -- --seeds 1 2 3 --size 400

Everything after the lone -- is ignored by Blender and left for the script, which reads it in the ordinary Python way:

argv = sys.argv[sys.argv.index("--") + 1:] if "--" in sys.argv else []
parser = argparse.ArgumentParser()
parser.add_argument("--seeds", type=int, nargs="+", default=[1, 2, 3])
parser.add_argument("--size", type=int, default=400, help="image size in pixels")
args = parser.parse_args(argv)

for seed in args.seeds:
    proclib.clear_scene()                                          # this also removes unused materials...
    land = proclib.material("Land", (0.35, 0.55, 0.3), roughness=0.9)     # ...so make ours afterwards
    vertices, faces = generators.terrain(seed=seed, size=8.0, cells=96, height=2.4)
    terrain = proclib.mesh_object(f"Terrain {seed}", vertices, faces, smooth=True)
    terrain.data.materials.append(land)
    proclib.camera_and_sun(location=(8, -8, 6.5), target=(0, 0, 0.4))

    for obj in bpy.context.scene.objects:
        obj.select_set(obj == terrain)
    bpy.context.view_layer.objects.active = terrain
    bpy.ops.wm.stl_export(filepath=os.path.join(out_dir, f"terrain-{seed:04d}.stl"), export_selected_objects=True)

    proclib.render_still(os.path.join(out_dir, f"terrain-{seed:04d}.png"), size=args.size)

The comment about materials records a real bug found while testing: the first version created the material once, before the loop, and clear_scene deleted it because nothing was using it yet.

Recording how something was made

Lesson 10 insisted on keeping the seed with every output. In Blender, store it on the object itself as a custom property, where it is saved with the file and visible in the Object properties:

obj["seed"] = seed
obj["generator"] = "procedural_tools.terrain 1.0.0"
obj["settings"] = "size=8.0 cells=96 height=2.4"

Key ideas

  • An add-on registers operators, properties and panels. Blender draws the controls.
  • bl_options = {"REGISTER", "UNDO"} gives the live adjust panel, which makes an operator feel procedural.
  • Keep generating functions in a module with no interface code.
  • An extension is a folder with a manifest. Blender's own command builds and checks the zip.
  • Three kinds of library: your modules, bundled packages, and asset libraries of node groups and materials.
  • --background turns Blender into a batch generator. Store the seed on what you make.

Blender challenge 4

Your Own Add-on

Package one of your generators from this course as a Blender add-on that someone else could install and use.

Requirements

  • At least one operator that generates geometry from a seed, with at least four properties that have sensible limits.
  • The live adjust panel works: changing a property after running regenerates the result.
  • A panel in the viewport sidebar, and an entry in the Add menu.
  • All generating code lives in a separate module that imports nothing from the interface.
  • A valid manifest, and the folder builds with blender --command extension build.
  • Generated objects carry their seed and settings as custom properties.
  • A batch script that uses the same generator module to produce files for a list of seeds without opening the window.
  • Enabling, disabling and re-enabling the add-on leaves no errors in the console.

Hints

  • Start from the starter add-on and get an empty operator registering before adding any generating code.
  • Add a poll class method to an operator to say when it is allowed to run, for example only in Object Mode.
  • Port a generator from JavaScript by keeping the structure and swapping PA.rng for random.Random and PA.noise for mathutils.noise.

You are done when

  • A fresh copy of Blender can install the zip and use the tool with no other set-up.
  • The batch script and the button produce identical geometry for the same seed.
