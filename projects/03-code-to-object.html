Project 3

From Code to Object

Grow a form with an algorithm, turn it into clean geometry a machine can follow, make it, and document it. The result is a physical object and a page that tells someone else exactly how it was produced.

The brief

Make one object you would keep: a pendant, a coaster, a lampshade, a plotted drawing, a cut panel, a small vessel. Its form must come from a growth algorithm, and it must be made by a machine from a file your code wrote.

The joining idea: millimetres, and a preflight you trust

On screen, anything you can draw exists. A machine is stricter. A wall thinner than the nozzle is not printed. A shape that is not joined to the rest falls out of a laser-cut sheet. A form two millimetres wider than the bed stops the job.

Two habits deal with this. First, design in millimetres from the first line, and convert to pixels only to preview. Second, write the checks as code, and run them every time, so that you never have to remember to look.

The example measures a shape and tests it against three rules. Raise the wobble until it fails, and see which rule catches it.

The shape in the example is a noisy circle, which is not grown and has only one outline. A grown form has branches, holes and thousands of points, and its checks are harder: is it all one piece, is every branch thick enough, does anything cross itself? Writing those checks is a large part of this project.

Milestones

1 · Machine first

Choose the machine, the material and the size before writing any code. Write down the limits as constants: working area, smallest feature, and for a printer the layer height and steepest overhang. Find them from the machine's documentation or by asking the person who runs it. If you guess, say that you guessed.

2 · Grow

A growth algorithm working in millimetres, inside a boundary that is the outline of your object. Let the machine's limits set the algorithm's parameters: the spacing between branches should come from the smallest feature and not from what looks good on screen.

3 · Clean

Turn the growth into geometry. Join points into paths. Remove duplicates and stubs too short to make. Simplify without losing the character. Resample so that spacing is even.

4 · Make it buildable

Lines have no width. For cutting and printing, give the form thickness by offsetting, and join it to a frame, a base or a ring so that it is one piece. For Route B, build a mesh and confirm it is watertight. For a plotter, order the paths to shorten travel.

5 · Preflight

Checks in code, run before every export, with a clear pass or fail on screen: fits the working area, nothing thinner than the smallest feature, one connected piece, and for Route B a watertight mesh with a flat base. An export button that refuses to work when a check fails is worth having.

6 · Proof

Export, and open the file in the machine's own software. Look at its preview carefully. Then make a small or quick test: a corner, a reduced size, a draft setting. Expect to go back to milestone 2 at least once. That is normal.

7 · Make and document

Make the object. Photograph it. Write a page with the photograph, a screenshot of the generator, the seed and every parameter, the machine and its settings, the material, and what went wrong on the way.

Project 3

The Object

A physical thing whose form was grown, and a record that would let someone make it again.

Requirements

  • Techniques from at least four of the lessons in the table above, including growth, geometry and a fabrication lesson, listed in a comment at the top of your file.
  • The form comes from a growth algorithm written by you, confined to the outline of the object.
  • All geometry is in millimetres. The machine's limits are named constants, and at least one growth parameter is derived from them.
  • A cleaning stage that is separate from the growth stage, and can be switched off to see the difference.
  • The exported form is one connected piece, or a deliberate set of pieces, with real thickness.
  • At least four automated checks, shown on screen as pass or fail, and export is blocked while any fails.
  • An SVG or STL export at true size, which opens at the correct dimensions in the machine's own software.
  • A recipe file saved with each export: seed, parameters, machine limits and date.
  • A documentation page stating plainly which stages were carried out, including any that were not.

Hints

  • Start small. A 60 mm object teaches the same things as a 200 mm one, in a tenth of the machine time.
  • To test for one connected piece, draw the thickened form to a small offscreen canvas and flood fill from one filled pixel. If any filled pixel was not reached, there is more than one piece.
  • To thicken a branching structure simply, stroke its paths with round caps and joins on a canvas, then trace the outline of the result.
  • For a relief or pendant on Route B, a height field over the thickened shape is enough: height from the canvas, sides and base added, as in Printing 2.
  • Measure a real feature on your first test with a ruler or calipers and compare it with the number in your code. If they differ, find out why before going on.
  • Keep every failed test piece. Photographed in a row, they are the best part of the documentation.

Stretch goals

  • A small edition: five objects from five seeds, which clearly belong together.
  • Both routes from the same growth: a plotted drawing and a printed relief of one form.
  • Growth that responds to the object's function: denser where a pendant hangs from its loop, open where a lampshade should pass light.
  • For a P1S, a custom toolpath as in Printing 5, in place of a sliced mesh.
  • A page where a visitor picks a seed and downloads a file for their own machine, with the checks running in their browser.

You are done when

The object is in your hand, or the file has passed your checks and the machine's own preview, and someone else could reproduce it from your page without asking you a question.
