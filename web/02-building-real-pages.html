Web Design 2

Building Real Pages

An effect in a square test canvas is half the job. On a real page it has to fill a responsive layout, sit behind real text, load without delaying the content, behave on phones, and respect people who do not want motion. This lesson walks through three complete pages.

The three demos on this page are ordinary stand-alone web pages in the course's web/demos folder. Each is embedded below in a frame, with a link to open it full size. Read their source: they are short, and written to be read. All three were loaded and checked with the pointer over them. They were not tested on a phone.

Demo 1: a landing page with a reveal hero

This is the dual-design reveal from the last lesson as a complete landing page for an imaginary studio. Move the pointer across the hero.

Open this demo in its own tab

Layering canvas and content

The hero is a positioned box. The canvas fills it, and the navigation and headline are ordinary HTML placed on top. The text is therefore real text: selectable, readable by search engines and screen readers, and styled with CSS. The canvas is marked aria-hidden because it is decoration.

.hero { position: relative; height: 100vh; overflow: hidden; }
.hero canvas { position: absolute; inset: 0; width: 100%; height: 100%; }
.hero nav, .hero .copy { position: absolute; left: 0; right: 0; padding: 0 6vw; }

/* "difference" inverts the text against whatever is behind it, so it reads on both designs */
.hero nav, .hero h1, .hero p { color: #fff; mix-blend-mode: difference; }

The last rule solves a real problem. The headline sits over a light design and, inside the blob, over a dark one. No single text colour is readable on both. With mix-blend-mode: difference, white text shows as the inverse of what lies beneath it: dark on the light design, light on the dark one, switching letter by letter as the blob passes.

Sizing a canvas properly

A canvas has two sizes: the size it is displayed at, set by CSS, and the number of pixels it holds, set by its width and height. If they do not match the picture is blurry or stretched. The pattern below keeps them in step, and scales drawing so that your code can work in ordinary CSS pixels.

function build() {
  const dpr = Math.min(devicePixelRatio || 1, 2);            // never render more than 2x: it is wasted work
  W = hero.clientWidth; H = hero.clientHeight;
  canvas.width = W * dpr; canvas.height = H * dpr;
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
  // ...draw the two designs onto hidden canvases of the same size...
}

new ResizeObserver(build).observe(hero);                       // rebuild whenever the hero changes size

Because the designs are generated from functions of W and H, they re-compose themselves for a phone, a laptop or a wide monitor. This is the unit-square discipline of Lesson 10 paying off.

Pointer position, relative to the element

hero.addEventListener('pointermove', (e) => {
  const box = hero.getBoundingClientRect();
  pointer.x = e.clientX - box.left;
  pointer.y = e.clientY - box.top;
  pointer.active = true;
});
hero.addEventListener('pointerleave', () => { pointer.active = false; });

Pointer events cover mouse, pen and touch with one set of handlers. When the pointer leaves, the demo goes back to its idle motion, so the hero is never frozen in an odd state.

Being a good guest

const calm = matchMedia('(prefers-reduced-motion: reduce)').matches;

// pause when the hero is scrolled out of view
new IntersectionObserver((entries) => { visible = entries[0].isIntersecting; }).observe(hero);

function frame(ms) {
  if (visible) { /* ...draw... */ }
  if (!calm) requestAnimationFrame(frame);
}

if (calm) drawStill(); else requestAnimationFrame(frame);     // reduced motion: one fixed frame

Demo 2: a reveal with no canvas at all

If the two designs can be made from HTML and CSS, the browser can do the masking itself. Here both layers are plain div elements with CSS gradients for artwork. The top layer is clipped to a circle whose position comes from CSS variables, and JavaScript's whole job is to copy the pointer position into those variables.

Open this demo in its own tab

.night {
  /* only a circle of this layer is visible, placed by three CSS variables */
  clip-path: circle(var(--r, 0px) at var(--x, 50%) var(--y, 50%));
}
x += (tx - x) * 0.12;                            // smoothing, as everywhere in the course
y += (ty - y) * 0.12;
r += (tr - r) * 0.08;
hero.style.setProperty('--x', x + 'px');
hero.style.setProperty('--y', y + 'px');
hero.style.setProperty('--r', r + 'px');

This CSS-variable bridge is the most useful pattern in creative web development. JavaScript computes a few numbers, and CSS uses them anywhere: in a clip path, a transform, a gradient position, a colour. The layers can contain anything, including images, video and live text, which a canvas cannot.

CSS featureWhat it gives you
clip-pathHard-edged masks: circles, polygons, insets. Fast and widely supported.
mask-image with a gradientSoft-edged masks. A radial gradient from opaque to transparent gives a feathered hole.
mix-blend-modeLayers that multiply, screen or invert against what is beneath
background with several gradientsPatterns with no image files: stripes, dots, grids, noise-like textures
SVG filters (feTurbulence, feDisplacementMap)Noise and liquid distortion applied to any element. Powerful, but heavy: test performance.
transform and opacityThe two properties browsers animate most cheaply. Prefer them for motion.

Choose canvas when the artwork itself is generated or needs an organic, changing mask. Choose CSS when the layers are ordinary page content.

Demo 3: generated covers for every article

A content page in which no article has an illustration. Each card's cover is drawn from its title, in one house style, and comes alive while hovered.

Open this demo in its own tab

Many small canvases raise a different problem from one large one: doing no more work than necessary.

// draw a cover only when its card first scrolls into view
const seen = new IntersectionObserver((entries) => {
  for (const entry of entries) {
    const state = cards.find((c) => c.canvas === entry.target);
    if (entry.isIntersecting && !state.drawn) { drawCover(state.canvas, state.title, 0); state.drawn = true; }
  }
});

// animate only the cards that need it
function frame() {
  for (const c of cards) {
    if (!c.drawn) continue;
    if (c.hover) c.life += 0.02;
    else if (c.life > 0.01) c.life *= 0.92;
    else continue;                                   // at rest: no drawing at all
    drawCover(c.canvas, c.title, c.life);
  }
  requestAnimationFrame(frame);
}

With a hundred cards on the page, at most one is being redrawn at any moment. For a site with thousands of items, generate the covers once on the server or at build time and serve them as ordinary images. The generator is the same code.

Checklists

Performance

  • Cap the device pixel ratio at 2.
  • Draw expensive, unchanging layers once onto hidden canvases and copy them each frame.
  • Stop the animation loop when the element is off screen or the tab is hidden.
  • Use requestAnimationFrame, never a timer, for animation.
  • Let the text and layout appear first. Start the canvas after the page has rendered, and show a static first frame immediately.
  • Measure on a mid-range phone. If it cannot hold 30 frames a second, reduce the particle count or resolution there.

Accessibility and robustness

  • Honour prefers-reduced-motion with a still image.
  • Mark decorative canvases aria-hidden="true". Keep all real content in HTML.
  • Check text contrast against every state of the background, not just the first frame.
  • Make sure the page is complete and usable if the script fails to load.
  • Never let a canvas capture clicks meant for links: set pointer-events: none on purely decorative layers.

Touch devices

  • There is no hover. The idle animation is what most phone visitors will see, so make it good.
  • Let a finger dragged across the element act as the pointer, without blocking page scrolling: add touch-action: pan-y.
  • Consider tilt as input, or tie the effect to scroll position instead.

Key ideas

  • Put the canvas behind real HTML content. Text stays text.
  • mix-blend-mode: difference keeps text readable over two different backgrounds.
  • Keep a canvas's pixel size in step with its displayed size, and rebuild on resize.
  • The CSS-variable bridge lets JavaScript drive any CSS property, including masks.
  • Draw once, copy often. Animate only what is visible and changing.
  • Reduced motion, touch and script failure are requirements, not extras.

Web design challenge

A Landing Page That Is Alive

Design and build a one-page site for a real or imaginary person, product or event, whose hero is a generative piece that responds to the visitor.

Requirements

  • A hero with a dual-design reveal of your own: two aligned treatments of one composition, and a mask with character.
  • Real HTML content over and below it: navigation, a headline, a paragraph, at least one further section.
  • A second generative element elsewhere on the page: seeded cards, a reactive divider, a living background.
  • One brand: two or three colours and one or two typefaces, used consistently in both the page and the generated art.
  • Responsive: it re-composes from 360 pixels wide to a wide monitor, with no horizontal scrolling.
  • A good idle state, a reduced-motion still, and animation that pauses off screen.
  • Text is readable in every state of the hero.
  • The seed can be set from the page address, so a particular version can be shared.

Hints

  • Design both hero treatments as still images first. If they are not good when still, motion will not save them.
  • Start from the starter file, which has the layering, sizing and good-guest code in place.
  • Shrink the browser window constantly while you work.

You are done when

  • Someone who has not seen it moves the mouse over the hero and smiles.
  • It works with the pointer, with a finger, and with neither.
