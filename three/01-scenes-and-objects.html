three.js 1

Scenes and Objects

three.js is the standard library for 3D in the browser. It handles cameras, lighting and the graphics card, so that you can spend your effort on the procedural part: deciding what goes where. Everything from the ten lessons carries over, with one more coordinate.

These pages need an internet connection. The rest of the course runs offline, but three.js is a large library, so these lessons load version 0.160 from a public content delivery network when the page opens. To work offline, install it with npm install three and point the import map at the top of each page to your local copy.

The five things in every three.js program

Scene
A container for everything that exists: objects, lights, fog.
Camera
The viewpoint. A perspective camera makes distant things smaller, like an eye.
Renderer
Draws the scene, as seen by the camera, onto a canvas using the graphics card.
Mesh
A visible object: a geometry (its shape, as triangles) plus a material (how its surface responds to light).
Light
Without one, lit materials are black.

A full program looks like this. In the live examples on these pages the renderer is created for you, already attached to the example's canvas, so the example code starts at the scene.

import * as THREE from 'three';

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(50, innerWidth / innerHeight, 0.1, 100);
camera.position.set(3, 2, 4);
camera.lookAt(0, 0, 0);

const cube = new THREE.Mesh(new THREE.BoxGeometry(1, 1, 1), new THREE.MeshStandardMaterial({ color: 0xe76f51 }));
scene.add(cube);
scene.add(new THREE.DirectionalLight(0xffffff, 3));

renderer.setAnimationLoop((ms) => {
  cube.rotation.y = ms / 1000;
  renderer.render(scene, camera);
});

Coordinates

three.js uses a right-handed system with Y up: X to the right, Y upward, Z toward the viewer. (The 3D printing lessons use Z up, as machines do. Converting is a swap of two axes.) Units are whatever you decide. Rotations are in radians. The camera's four numbers are its field of view in degrees, the aspect ratio, and the nearest and farthest distances it draws.

Try it: change BoxGeometry to TorusKnotGeometry(0.8, 0.3, 120, 16) or IcosahedronGeometry(1, 0). Set roughness to 0.05 and add metalness: 1. Delete the ambient light and look at the dark side.

Loops make worlds

A single object is not procedural art. The step that matters is the same as Lesson 1: a loop, a grid, and properties driven by a field. Here a grid of boxes takes its height and colour from noise, which is all a low-polygon landscape or a generated city is.

Two practical points. Create one geometry and reuse it for every mesh: only the position, scale and material differ. And scene.fog fades distant objects into the background colour, which is a cheap and effective cue for depth.

The scene graph

Objects can contain other objects. A child's position, rotation and scale are relative to its parent, so moving the parent moves everything inside it. This tree of objects is the scene graph, and it is the 3D form of the save, translate, rotate, restore pattern from Lesson 1.

It makes recursive structures natural. A branch is a group containing a cylinder and, at its tip, smaller branches. Each sub-branch only needs to know its own rotation relative to its parent. This is Lesson 6's fractal tree in three dimensions.

Materials and lights in brief

MaterialBehaviourUse
MeshBasicMaterialFlat colour, ignores lightsGraphic, poster-like work; fastest
MeshStandardMaterialPhysically based: roughness and metalnessThe default choice
MeshNormalMaterialColours each face by the direction it pointsChecking a shape while building it
LineBasicMaterial, PointsMaterialFor lines and for pointsWireframes, particles
ShaderMaterialYou write the GLSLLesson 3 of this section

Set flatShading: true on a standard material for a faceted, low-polygon look. For lights, a directional light plus a hemisphere light is a dependable start. Point lights and spotlights have positions and fall off with distance.

Key ideas

  • Scene, camera, renderer, meshes, lights. A mesh is a geometry plus a material.
  • Y is up. Rotations are radians. Units are yours to choose.
  • Procedural 3D is the same loops and fields as 2D, with one more coordinate.
  • Share geometries and materials between meshes.
  • The scene graph nests objects, so recursive structures build themselves.
  • Fog and a hemisphere light give depth for almost no effort.

Practice

Three exercises

  • Rule poster in 3D. Rebuild your Lesson 1 challenge as a grid of 3D shapes in which height, rotation and colour each follow a field. No randomness.
  • A city block. Start from T1.2. Make building footprints vary by recursive subdivision (Lesson 7), heights fall off with distance from a centre, and add a few very tall towers by weighted chance.
  • A grove. Plant a dozen trees from T1.3 on a noise terrain, each from its own seed, with size depending on the terrain height.
