Special Topic 1

Interactivity

A procedural artwork is a system of rules with dials. Interactivity means handing some of those dials to someone else: a visitor, a player, a microphone, a clock. This page covers where input comes from, how to connect it to a system, and how that is done on websites and in games.

The interaction loop

Every interactive piece runs the same loop, many times a second:

input → state → rules → picture → (the person reacts) → input …

  • Input is any signal from outside the program.
  • State is what the program remembers: positions, a grid, a seed, a mode.
  • Rules are everything from the ten lessons.

The design question is always the same: which signal drives which parameter, and how directly? The rest of this page is a catalogue of answers.

Mapping: direct and smoothed

The simplest connection is a direct mapping: one input value sets one parameter through PA.map. It is immediate and easy to understand. Its weakness is that hands are jittery, and a picture wired straight to the mouse twitches.

The fix is one line. Keep your own copy of the input and move it a fraction of the way toward the real value each frame:

smooth += (input - smooth) * 0.08;

That is a lerp toward a moving target. The picture gains weight and glide. A smaller fraction feels heavier, a larger one snappier. (A damped spring from Maths 4 does the same with a little overshoot.)

Input as a force

A more interesting connection is indirect. The system has its own behaviour, and the input only disturbs it. The visitor does not set values; they push on something that pushes back. This is why stirring a fluid simulation is more absorbing than dragging a slider: the system answers with something you did not exactly ask for.

Here the particles drift on a noise field by themselves. The cursor's velocity, not its position, is added to nearby particles, weighted by a bell curve of distance (Maths 1).

Co-creation: the generative brush

A third relationship splits the work. The person decides where and when. The system decides what. Drawing tools built this way let anyone make something that looks good, because the rules guarantee the quality of the marks while the gesture still belongs to the person.

Drag on the canvas below. You plant; the vines grow, wander on a noise field and branch by themselves. Two details are worth copying. The drawing persists, so the piece accumulates a history of the visit. And until someone touches it, a "ghost hand" draws slowly, so that the piece is never blank. Installations call this an attract mode.

Parameters as an interface

Sometimes the goal is not play but control: a tool in which someone explores a design space and picks a result. Then the right input is a labelled slider for each parameter. This is how generative tools for designers work, and how product configurators let a customer shape their own lamp or ring.

The craft is in choosing which parameters to expose. A system might have forty numbers inside it. A good tool exposes four or five that each make a visible, distinct difference, and keeps their ranges within values that always look good. In these examples ui.slider adds a control and returns a function that reads its current value.

Identity as a seed

Lesson 2 showed that a text seed always produces the same sequence of random numbers. That turns any piece of text into a unique, repeatable image. Type a name and you get its emblem, the same one every time and different from everyone else's.

This is among the most widely used interactive methods because the person's only action is to be themselves. It is how default avatars are generated on code-hosting and messaging sites, how event badges and personalised packaging are made, and how blockchain art platforms turn a transaction number into an artwork.

Sound

Audio becomes visual input through an analyser, which the browser provides. Many times a second it gives you an array of numbers: how loud the sound currently is in each band of pitch, from bass to treble. From there it is ordinary mapping.

  • Average the first few bands for the bass, and use it for big, slow things: scale, pulse, camera shake.
  • Use the upper bands for small, fast things: sparkle, line weight, jitter.
  • Smooth everything, or the picture flickers. Let values rise quickly and fall slowly.
  • A sudden jump in loudness is a beat. Use beats as triggers: change the seed, spawn particles, flip a mode.

The example plays its own quiet synthesiser so that it works without asking for microphone permission. The comment in the code shows the two lines that swap in the microphone.

Interactivity on websites

On a web page a generative piece is usually not the main event. It is a background, an illustration or a moment of delight, and it has to coexist with text, navigation and slow phones. These are the common patterns.

Scroll as a timeline

Reading a page is already an input: the reader scrolls. Convert the scroll position into a fraction from 0 to 1 and drive the piece with it, and the reader scrubs through your animation at their own pace, forwards and backwards. This is the technique behind "scrollytelling" articles.

The key requirement is that the piece is a pure function of progress: the same scroll position must always give the same picture. So the tree below is generated once from a fixed seed, and only the amount of it that is drawn depends on scrolling. Scroll this page slowly while the canvas is on screen.

The essential code for the first three, outside this course's example boxes:

// a canvas that always fills the window, at full sharpness
function resize() {
  canvas.width = innerWidth * devicePixelRatio;
  canvas.height = innerHeight * devicePixelRatio;
}
addEventListener('resize', resize);
resize();

// follow the cursor anywhere on the page
addEventListener('pointermove', (e) => { target.x = e.clientX; target.y = e.clientY; });

// a seed in the address bar: every output has a link
let seed = location.hash.slice(1) || String(Date.now());
location.hash = seed;
addEventListener('hashchange', () => draw(location.hash.slice(1)));

// phone tilt, in degrees
addEventListener('deviceorientation', (e) => { tiltX = e.gamma; tiltY = e.beta; });

Being a good guest on a web page. Stop animating when the canvas is off screen or the tab is hidden. Check matchMedia('(prefers-reduced-motion: reduce)') and show a still image to people who have asked for less motion. Never make content depend on the animation. Test on a phone: a piece that runs at 60 frames a second on a desktop may manage 10 on an old handset, so lower the particle count or resolution when frames are slow.

Interactivity in games

Games are the largest users of procedural methods, and they use them in two distinct ways.

1. Generating the world the player explores

The player's movement is the input, and content is generated to meet it. The central idea is that the world is a function. Nothing is stored. Any location can be computed from its coordinates and a seed, so the world is effectively infinite and yet identical every time you return, and two players with the same seed see the same place.

The whole world below is the function tileAt. Noise gives the terrain (Lesson 3) and a hash of the tile's coordinates decides where trees stand. Click the canvas, then walk with the arrow keys or W, A, S, D. You can walk for ever.

2. Giving the player a system to play with

In the second kind, the rules themselves are the toy. The player adds things to a simulation and watches the consequences. "Falling sand" games are the classic case: a cellular automaton (Lesson 8) in which each grain falls straight down if it can, and otherwise slides diagonally. Those two rules are enough to produce heaps, slopes and avalanches. Add rules for water, fire and plants and you have a genre.

Two engineering constraints shape all of this. Determinism: the same seed must give the same world on every machine, or multiplayer and saved games break, which is why games use their own seeded generators exactly as Lesson 2 did. Budget: everything must finish within a sixtieth of a second, so worlds are generated in chunks, near the player, a little each frame.

Principles

  • Respond at once. Something visible should happen within a tenth of a second of any action, even if the full consequence unfolds slowly.
  • Let the rule be discoverable. People enjoy working out what their input does. Too direct is dull, too obscure feels broken.
  • Smooth the input. Raw signals jitter.
  • No input should make it ugly. Clamp ranges and design the system so that every reachable state is a good one. This is Lesson 10's rule for long-form art, applied to a person instead of a seed.
  • Never be blank. Give the piece an idle behaviour.
  • Reward small actions generously. A flick of the wrist should produce more than a flick's worth of result.
  • Decide what persists. Marks that stay give a sense of authorship. Marks that fade invite continuous play. Always provide a reset.

Key ideas

  • Interactivity is an outside signal driving a parameter of a generative system.
  • Direct mapping sets values. Indirect mapping applies forces to a system with its own behaviour.
  • In co-creation the person chooses where and when, and the rules choose what.
  • Text, dates and identifiers become seeds: unique and repeatable.
  • On the web, scroll, cursor and address are the native inputs, and the piece must be a polite guest.
  • In games, the world is a function of coordinates and a seed, or the rules themselves are the toy.

Special challenge 1

The Instrument

Build an interactive generative piece that someone could happily play with for five minutes without instructions. Think of it as a visual instrument: the person performs, and the system gives the performance its character.

Requirements

  • At least three input channels of different kinds, for example pointer, keyboard, and one of time, text, sound or scroll.
  • At least one indirect mapping: an input that acts as a force on a simulation, not as a value.
  • All continuous inputs are smoothed.
  • An attract mode: it does something interesting when untouched, and hands over the moment someone interacts.
  • No sequence of inputs produces an ugly or broken picture.
  • Keys to reset, to save a PNG, and to start from a new seed.
  • The seed lives in the page address, so that a starting state can be shared as a link.

Hints

  • Start from a system you already built for an earlier challenge, and ask what a person could push on.
  • Give someone else the mouse and watch without explaining. Whatever they try first should do something.
  • For pointer speed, keep last frame's position and subtract.

Stretch goals

  • Microphone input, with beats as triggers.
  • Make it work by touch on a phone, including tilt.
  • Record a performance as a list of timed inputs and replay it exactly. This only works if the piece is deterministic.

You are done when

  • A person who has never seen it finds all three inputs without help.
  • Two people playing it produce recognisably different results.
