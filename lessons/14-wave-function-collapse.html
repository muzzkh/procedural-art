Lesson 14

Wave Function Collapse

Lesson 2 placed tiles at random and enjoyed the accidents. Wave Function Collapse places tiles so that every neighbour fits, everywhere, and still looks random. It is the algorithm behind a great many generated game levels, cities and patterns, and it is simpler than its name.

The problem

You have a set of tiles and a rule about which may sit beside which. You want to fill a grid so that the rule holds at every border between cells, with as much variety as the rule allows. Filling the grid at random breaks the rule constantly. Filling it in reading order and hoping works only for simple tilesets. Wave Function Collapse, published by Maxim Gumin in 2016, solves it with two ideas: decide the most constrained cell first, and after every decision, work out all its consequences.

The name is borrowed from quantum physics, loosely. Each cell starts as a blur of every possibility and "collapses" to one. Nothing quantum is involved.

Tiles and sockets

The neatest way to state which tiles fit together is to label each tile's four edges. The labels are called sockets. Two tiles may touch if the two edges that meet carry the same label.

The tileset here is a set of pipes. Each edge is either 1, a pipe crosses it, or 0, it does not. A tile is fully described by its four sockets in the order top, right, bottom, left, and can be drawn from them. Rotating a tile shifts the list round by one place, so six hand-made shapes give sixteen tiles.

Scattered at random, they make a mess. The red marks show every border where a pipe meets a blank edge.

The algorithm

Every cell keeps a list of the tiles it could still be. At the start that is every tile. Then repeat:

  1. Observe. Find the undecided cell with the fewest remaining options. The number of options is called its entropy. Low entropy means a cell is nearly forced, so it is the one most likely to become impossible if left until later.
  2. Collapse. Choose one of that cell's options at random and discard the others.
  3. Propagate. The choice restricts the neighbours: any tile of theirs that cannot fit beside the chosen one is removed. If a neighbour lost options, its neighbours may now lose some too, so the consequences are followed outward until nothing changes.

Stop when every cell has exactly one option. If a cell ever reaches zero options there is a contradiction: the choices so far cannot be completed.

The example runs the algorithm a few steps per frame. Undecided cells show how many options they have left, darker for fewer. Watch decisions spread outward from each collapsed cell as its neighbours' numbers drop.

With all sixteen pipe tiles, every combination of sockets exists, so a contradiction can never happen here. That is unusual. Most interesting tilesets are incomplete.

Contradictions, weights and borders

Three refinements turn the bare algorithm into a design tool. PA.wfc is the code above with these added.

Contradiction handling
If a cell runs out of options, the simplest cure is to throw the grid away and start again. For most tilesets a few restarts are enough. Serious implementations backtrack instead: undo the last few decisions and try differently.
Weights
Give each tile a weight, and collapse by weighted choice. Weights do not change what is possible, only how often each tile appears, which is how you set the character of the output.
Border constraints
Restrict cells before starting: for example, require a blank socket on every outside edge so that no pipe runs off the grid. Any cell can be fixed in advance this way, which lets you place a doorway or a river by hand and have the rest generated round it.

Here the tileset has lost its dead-end and its crossing, so some arrangements cannot be completed, and the outside border must be blank. The readout reports how many restarts were needed. The slider changes the weight of the straight pieces.

Richer sockets: a landscape

Sockets can be any labels, not just on and off. For terrain, label each tile's four corners with a terrain type, and make a tile's edge socket the pair of corners along that edge. Two tiles then fit when the corners they share agree, which is exactly what you want for a map.

The design rule goes into which tiles exist. Here a tile may combine water with sand, or sand with grass, or grass with forest, but never terrains that are further apart. No tile contains both water and grass, so the algorithm cannot put them side by side, and a beach appears between them everywhere without any code that mentions beaches. Tiles with four equal corners get a high weight, which makes regions large.

Key ideas

  • Label tile edges with sockets. Tiles fit where the meeting sockets are equal.
  • Each cell holds the set of tiles it could still be.
  • Collapse the cell with the fewest options, then propagate the consequences until nothing changes.
  • A cell with no options is a contradiction: restart or backtrack.
  • Weights set how often tiles appear. Which tiles exist sets what can appear.
  • Design the tileset and the rules. The algorithm only enforces them.

Common mistakes

  • Sockets listed in an inconsistent order, so that tiles match in the wrong direction. Decide the order once and draw a test grid.
  • Forgetting rotations, which leaves a tileset that can hardly ever be completed.
  • Expecting large-scale structure. The algorithm only knows about neighbours, so its output is locally correct and globally shapeless unless you add weights, pre-set cells or a guiding field.

Challenge 14

Your Own Tileset

Design a tileset with a character of its own and use Wave Function Collapse to build something from it: a circuit board, a city plan, a knot pattern, a garden, a dungeon.

Requirements

  • At least eight tile shapes that you designed and draw in code, expanded by rotation.
  • At least three socket types, not just on and off.
  • At least one tile that is rare by weight, and gives the output its points of interest.
  • A border rule or some pre-set cells, so that the result is framed or built round something you placed.
  • Your own solver, or PA.wfc, with the number of restarts reported.
  • Seeded. A key gives a new seed, and the grid is at least 20 × 20.
  • A way to see the tileset itself: a key that shows every tile with its sockets marked.

Hints

  • Draw the tileset view first, and check every tile by eye before solving anything.
  • If the solver often fails, look for a combination of sockets that no tile provides, and add the missing tile.
  • Draw tiles from their sockets where you can. Then a new tile is one more line of data.

Stretch goals

  • Let noise bias the weights across the canvas, so that different regions have different character.
  • Write the solver yourself with backtracking instead of restarts.
  • Animate the collapse, as in example 14.2, as part of the finished piece.

You are done when

  • Ten seeds all solve, and all look like the same world.
  • Someone could guess what the tiles represent.
