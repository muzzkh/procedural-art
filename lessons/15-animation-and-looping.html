Lesson 15

Animation and Looping

Many examples in this course move, but none was designed as motion. This lesson is about time as a material: how things speed up and slow down, how to make a loop with no visible join, how to give movement rhythm, and how to get the result out as video.

Animation is a function of time

The most useful way to think about animation is the one used throughout the course: the picture is a function, and time is one of its inputs. If the frame at any moment can be computed from the time alone, without depending on the frames before it, then the animation can be paused, reversed, looped, and rendered at any frame rate. Simulations cannot do this, since each step needs the last, but most designed motion can.

Almost all designed motion is built from one small pattern:

progress (0 to 1) → easing → lerp between a start and an end

Easing

Things in the world do not start and stop instantly. An easing function is a shaping function (Maths 1) applied to progress: it takes a steady 0 to 1 and returns a 0 to 1 that accelerates, decelerates, overshoots or bounces. The choice of easing is most of what gives motion its character.

Perfect loops

A looping animation, as a GIF or a short video, must end exactly where it began, with the same positions and the same velocities, or the join shows as a jump or a stutter. The reliable method is to drive everything from a single phase that runs from 0 to 1 over the loop, and to use only functions of the phase that return to their starting value:

  • Sines and cosines of phase × TAU × k, where k is a whole number. Any whole number of cycles fits exactly.
  • Noise sampled round a circle. Walk once round a circle in noise space during the loop (Lesson 3). The end of the circle is its beginning, so the noise value returns smoothly.
  • Motion that wraps. Something travelling a whole number of steps of a repeating pattern, such as a row of dots moving along by exactly one spacing.

What breaks a loop is anything else: random numbers drawn each frame, noise moving in a straight line, sines with fractional frequencies, and accumulating simulations.

Staggering and rhythm

If a hundred things all move at the same instant, the eye sees one event. If each starts a little after its neighbour, the eye sees a wave travelling through them, and a simple move becomes rich. This is staggering, and it is the cheapest way to make motion look choreographed.

Give every element a delay, and compute its own local progress from the global one. The delay is a field: distance from a point gives a ripple, the column number gives a sweep, noise gives an organic scatter, and a random value gives sparkle.

local = clamp((progress - delay) / duration)

Rhythm is the pattern of moving and resting. Motion that never stops is tiring. Good loops have beats: a move, a hold, a move back, a hold. The example plays a move out and back with holds between, using a triangle wave for the back-and-forth.

Timing guidelines

  • Interface motion is short: 150 to 400 milliseconds. Longer feels sluggish.
  • Loops for sharing run 2 to 6 seconds. Shorter is frantic, longer makes large files.
  • Hold the key poses. Give the viewer a moment to see the start and end states.
  • Overlap actions. Let one thing finish while the next begins. Strictly sequential motion looks robotic.
  • Vary one thing. If position, scale, rotation and colour all change at once in different ways, nothing reads. Let one lead.
  • Frame rate: 60 frames per second for screens, 30 for most video, 24 for a film look. Because the animation is a function of time, it does not care.

Exporting

There are two ways to get animation out of the browser.

Recording the canvas

The browser can record a canvas directly to a video file. canvas.captureStream() turns the canvas into a video stream and a MediaRecorder saves it. This is quick, and records whatever actually appeared on screen, so a slow sketch gives a stuttering video. Press the button to record one loop of the example and download it as a WebM file.

Rendering frame by frame

For the best quality, do not record in real time. Step through the frames yourself, compute each one from its frame number, and save each as an image. A slow sketch then simply takes longer to render and the result is perfectly smooth. This works only if the animation is a function of time, which is one more reason to write it that way.

const FPS = 60, SECONDS = 4, FRAMES = FPS * SECONDS;

async function renderAll() {
  for (let frame = 0; frame < FRAMES; frame++) {
    drawFrame(frame / FRAMES);                                  // your picture, as a function of phase
    const blob = await new Promise((done) => canvas.toBlob(done));
    const link = document.createElement('a');
    link.href = URL.createObjectURL(blob);
    link.download = 'frame-' + String(frame).padStart(4, '0') + '.png';
    link.click();
    await new Promise((done) => setTimeout(done, 60));          // give the browser time to save
  }
}

Join the numbered images into a video with the free command-line tool ffmpeg:

ffmpeg -framerate 60 -i frame-%04d.png -pix_fmt yuv420p loop.mp4

That listing and command are standard practice but were not run as part of preparing this lesson. The live recording example above was.

Key ideas

  • Write animation as a function of time, not as a sequence of changes.
  • Progress, then easing, then lerp. Easing gives motion its character.
  • A perfect loop uses a phase from 0 to 1 and only functions that return to their start: whole-number sines, and noise on a circle.
  • Staggering gives each element a delay taken from a field.
  • Rhythm needs rests. Hold the poses.
  • Record the canvas for speed, or render frame by frame for quality.

Common mistakes

  • Adding a fixed amount each frame, which runs at different speeds on different screens. Use the time.
  • Calling a random function inside the frame loop, so the picture flickers and cannot loop.
  • Easing everything with the same curve and duration. Vary them a little.

Challenge 15

The Perfect Loop

Make a looping animation, between two and six seconds long, that could run for ever on a wall with no visible join, and export it as a video.

Requirements

  • The whole picture is a function drawFrame(phase), with phase from 0 to 1. Calling it with the same phase always draws the same thing.
  • The loop is seamless: drawFrame(0) and drawFrame(1) are identical, and so is the motion on either side of the join.
  • At least forty moving elements, staggered by a field.
  • At least two different easings, and at least one hold where the picture rests.
  • Organic variation from noise sampled on a circle.
  • A key that scrubs: holding it lets the mouse position set the phase, so you can inspect any frame.
  • Exported as video, by recording or frame by frame.

Hints

  • Design two or three key poses as still images first. The loop is the journey between them.
  • To test the join, draw phase 0 and phase 0.999 side by side. They should be nearly indistinguishable.
  • Use whole numbers for every frequency. One fractional value is enough to break the loop.

Stretch goals

  • Frame-by-frame export at 1080 × 1080 and 60 frames per second.
  • A second version of the loop from a different seed, that could play beside the first.
  • Sound that loops with it (Special Topic 4).

You are done when

  • You have watched it loop twenty times and cannot say where it restarts.
  • A still taken from any moment looks composed.
