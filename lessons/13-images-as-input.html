Lesson 13

Images as Input

A photograph is a field: a brightness for every point. Feed that field into any of the systems you have built, in place of noise, and the system draws the photograph in its own handwriting. This lesson covers halftones, engraving, dithering, stippling, edge detection and pixel sorting.

An image is a field

Since Lesson 1 a field has meant a rule that gives a number for every position. Until now the rule was a formula or noise. An image is the same thing with the numbers stored instead of computed: ask for the brightness at (x, y) and you get a value from 0 to 1.

So nothing new is needed. Wherever a sketch said N.get(x, y), it can say image.at(x, y), and the output takes on the shape of the picture.

The examples use PA.testImage(size), which generates a small greyscale "photograph" of a lit ball on a floor, so that the course needs no image files. It returns the pixel data plus an at(x, y) function. Swapping in your own photo is covered at the end.

Halftone: brightness as size

Printing presses cannot print grey, only ink or no ink. Newspapers solved this in the 1880s with the halftone: a regular grid of dots whose size varies. Large dots read as dark, small as light. It is Lesson 1's grid with the image as the field.

The square root matters. Ink coverage is the dot's area, which grows with the square of the radius, so the radius must follow the square root of darkness for tones to come out right. The screen is rotated because a pattern at 45° is much less noticeable to the eye than a horizontal one.

Engraving: brightness as line weight

Banknotes and old book illustrations shade with lines that swell and thin. Draw rows of lines across the image and set each short piece's width from the darkness beneath it. Give the lines a wave and the result looks cut by hand.

Dithering: only black and white

Dithering reduces an image to pure black and pure white pixels while keeping the impression of grey. It was essential for early screens and printers, and is used now for its look. Three methods, in rising quality:

Threshold
Black if darker than half, otherwise white. All the mid-tones are lost.
Ordered
Compare each pixel with a threshold that varies in a small repeating pattern, the Bayer matrix. Gives a regular cross-hatch texture.
Error diffusion
Decide each pixel in turn, then pass the error you just made on to the neighbours not yet decided, so that it averages out. Floyd and Steinberg's 1976 method is the classic. It gives the most faithful, organic result.

Stippling: brightness as probability

Maths 5 showed that keeping random points with a probability equal to darkness turns chance into shading. With an image as the darkness function, that is a stipple portrait. It looks better still when the dots are evenly spaced, which is what Lesson 7's Poisson-disc sampling is for: allow the minimum spacing to shrink where the image is dark.

Reading structure: gradients and edges

Brightness is not the only thing an image can tell a system. Its gradient (Maths 3) says where brightness is changing and in which direction, and that reveals structure:

  • Where the gradient is large there is an edge. Measuring it at every pixel is edge detection. The Sobel operator does it with a weighted difference of the pixel's neighbours.
  • The gradient's direction points across an edge. Turned a quarter turn, it runs along the form, which is the direction a draughtsman's hatching follows.

The left panel shows the strength of the gradient: an edge map. The right panel draws short strokes along the contours, with length and weight set by darkness. That is a flow field (Lesson 5) whose angles come from an image instead of from noise.

Pixel sorting

Some image effects rearrange the pixels themselves. In pixel sorting, popularised by the artist Kim Asendorf around 2010, each row or column is scanned for runs of pixels brighter than a threshold, and each run is sorted by brightness. Detailed areas dissolve into smooth streaks while dark areas stay intact, as if the picture were melting.

Using your own photograph

Any image can replace the test picture. Draw it onto a hidden canvas and read the pixels, which is all PA.testImage does. The simplest reliable way to load a file in a page opened from your own disk is a file picker:

<input type="file" id="pick" accept="image/*">

document.getElementById('pick').addEventListener('change', (e) => {
  const photo = new Image();
  photo.onload = () => {
    const hidden = document.createElement('canvas');
    hidden.width = hidden.height = 300;
    const g = hidden.getContext('2d');
    g.drawImage(photo, 0, 0, 300, 300);                       // scaled to 300 x 300
    const pixels = g.getImageData(0, 0, 300, 300).data;

    // brightness from 0 to 1, weighting green most, as the eye does
    const at = (x, y) => {
      const k = (Math.floor(y) * 300 + Math.floor(x)) * 4;
      return (0.2126 * pixels[k] + 0.7152 * pixels[k + 1] + 0.0722 * pixels[k + 2]) / 255;
    };
    draw(at);                                                 // your sketch, given the new field
  };
  photo.src = URL.createObjectURL(e.target.files[0]);
});

Loading an image by its file name instead (photo.src = 'portrait.jpg') works when the page is served by a web server. Opened straight from disk, browsers refuse to let a script read the pixels of such an image, as a security measure. The file picker avoids the problem.

Choose source images with strong, simple tones. Most of these techniques throw away detail, and a photograph with a clear subject against a plain background survives best. Raise the contrast before sampling.

Key ideas

  • An image is a field of brightness. Use it wherever you used noise.
  • Halftone maps darkness to dot size, by area. Engraving maps it to line weight.
  • Dithering represents grey with black and white. Error diffusion passes each mistake on to its neighbours.
  • Stippling keeps points with a probability equal to darkness.
  • The image's gradient gives edges, and the direction for strokes that follow form.
  • Read a photo's pixels by drawing it to a hidden canvas.

Common mistakes

  • Sampling a huge photo at full size. Scale it down first: 300 pixels across is plenty for most treatments.
  • Forgetting the square root in a halftone, which makes mid-tones too light.
  • Marks so fine or so coarse that the image is lost. Squint at the result: the subject should still be there.

Challenge 13

A Portrait in Marks

Build a tool that redraws any photograph in a mark-making style of your own invention, good enough to print.

Requirements

  • A file picker loads the user's own image. Until one is chosen, the tool shows a generated test image.
  • The image drives at least two different properties of your marks: for example size and angle, or density and colour.
  • At least one property uses the image's gradient, not just its brightness.
  • The marks are your own design, not plain dots: strokes, small shapes, letters, loops.
  • A contrast control and a density control, as sliders or keys.
  • Seeded, so that the same photo and seed always give the same drawing.
  • Output at print resolution: the drawing is produced at 2400 pixels or more, or as SVG.

Hints

  • Get it working on the test image first. Its simple tones make problems obvious.
  • Work in unit coordinates so that the preview and the print render come from the same code.
  • Blur the source slightly before taking gradients. Photographs are noisy, and noise makes stroke directions jitter.

Stretch goals

  • Use colour: sample the photo's hue and map it onto a limited palette from Lesson 11.
  • Plotter output: lines only, sorted to reduce pen travel (Special Topic 3).
  • Animate the drawing being made, stroke by stroke.

You are done when

  • Three very different photographs all give a recognisable, attractive result.
  • People ask what technique it is.
