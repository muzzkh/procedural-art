Lesson 9

Shaders and Distance Fields

So far you have told the computer which shapes to draw. A shader turns the question round: for this one pixel, what colour should it be? Answer that with a formula and the graphics card will evaluate it for every pixel at once, sixty times a second.

Thinking per pixel

You have already written per-pixel code: the terrain in Lesson 3, the Mandelbrot set in Lesson 6. The pattern was a double loop over x and y, with a function inside that computed a colour from the position. A fragment shader is exactly that inner function. You never write the loop. The function has no memory and cannot see other pixels: it receives a coordinate and returns a colour.

The first step in almost every shader is to convert the pixel coordinate into a convenient one, usually with the origin at the centre and the vertical range running from −1 to 1.

Signed distance functions

If a pixel cannot draw a circle, how do you get one? By asking of every pixel: how far am I from the edge of the circle?

A signed distance function (SDF) returns the distance from a point to the nearest edge of a shape: negative inside, zero exactly on the edge, positive outside. For a circle of radius r centred on the origin it is one line: the distance from the origin, minus r.

Here is that idea in ordinary JavaScript first, so that nothing new is involved except the idea itself.

The distance gives you more than inside or outside. You get the outline (where d is near zero), a glow (brightness falling with d), contour rings (a sine of d), and soft edges, all from one number.

GLSL in five minutes

Shaders are written in GLSL, a small language that looks like C. The differences from JavaScript that matter:

  • Types are declared: float d = 0.5;. Decimal numbers must have a decimal point: write 2.0, not 2.
  • Vectors are built in: vec2, vec3, vec4. Arithmetic works on all components at once, and you can pick components by name: p.x, p.xy, col.rgb.
  • Useful functions are built in, and are the vocabulary of shader writing:
FunctionMeaning
length(v)Length of a vector, so distance from the origin
mix(a, b, t)The same as lerp
step(edge, x)0 if x is below the edge, otherwise 1. A hard threshold.
smoothstep(a, b, x)A smooth ramp from 0 to 1 as x goes from a to b. A soft threshold.
fract(x)The fractional part. Makes anything repeat.
abs, min, max, clamp, sin, cos, atan, pow, exp, dotAs you would expect

In the shader examples on this page, three inputs are provided: u_res (the canvas size in pixels), u_time (seconds) and u_mouse (pixels). gl_FragCoord.xy is the current pixel's position, and you set gl_FragColor to the colour you want, as red, green, blue and alpha from 0 to 1.

Try it: change 0.01 in the smoothstep to 0.3 for a blurred edge. Replace length(uv) with max(abs(uv.x), abs(uv.y)) and the circle becomes a square, because that expression is the distance in a different sense.

Combining shapes

The real power of distance functions is that shapes combine with arithmetic:

OperationFormula
Union (either shape)min(a, b)
Intersection (both)max(a, b)
Subtraction (a with b cut out)max(a, -b)
Outline or ringabs(a) - thickness
Grow or round the cornersa - amount
Smooth union (shapes melt together)smin(a, b, k), defined below

The smooth union is the one that makes SDF art look the way it does: shapes that approach each other reach out and merge like drops of liquid.

Try it: replace each smin(..., 0.25) with plain min(...) to see the hard union. Then try max(d, -sdCircle(...)) to make the circles carve holes.

Bending space

A shape is a function of position. So if you alter the position before handing it to the shape, the shape changes. This is called a domain operation, and one line can have a dramatic effect:

Change to the coordinateEffect
p - offsetMoves the shape
p * rotation matrixRotates it
abs(p)Mirrors it across both axes
fract(p) - 0.5Repeats it for ever in a grid
p + noise(p)Warps it (Lesson 3's domain warping)

The repetition trick is worth understanding. fract throws away the whole-number part of a coordinate, so every unit square of the plane ends up with the same local coordinates and draws the same shape. The whole-number part, floor(p), tells you which cell you are in, which you can use to make each copy a little different.

This example also introduces the cosine palette, the same one behind PA.cosPalette. Three cosine waves, one per colour channel, slightly out of phase, give a smooth endless colour ramp from a single number. Changing the phase offsets changes the whole colour scheme.

Noise in a shader

GLSL has no random or noise function, so shader writers build their own, usually the value noise you wrote in Lesson 3. The hash is a notorious one-liner: take a sine, multiply by a huge number, and keep the fractional part. With noise available, fBm and domain warping follow exactly as before, and because they now run on the graphics card they can animate at full speed.

A glimpse of three dimensions

Distance functions work in 3D without change: a sphere is still length(p) - r, with p now a vec3. To render a 3D scene, each pixel fires a ray from a camera and walks along it. At every stop it asks the scene's distance function how far the nearest surface is, and steps forward by exactly that much, since it cannot hit anything sooner. When the distance becomes tiny it has arrived. This is raymarching, also called sphere tracing. Everything from this lesson (smooth unions, repetition, warping) carries straight over, which is how single-shader 3D worlds are made.

Key ideas

  • A fragment shader is a function from pixel position to colour, run for all pixels in parallel.
  • A signed distance function returns how far a point is from a shape's edge. Negative means inside.
  • smoothstep on a distance gives clean anti-aliased edges.
  • Shapes combine with min, max and smin.
  • Changing the coordinate before evaluating a shape moves, rotates, mirrors, repeats or warps it.
  • A cosine palette turns one number into a smooth colour ramp.
  • The same toolkit extends to 3D through raymarching.

Common mistakes

  • Writing 2 where GLSL wants 2.0. Whole-number and decimal types do not mix.
  • Forgetting the aspect-ratio correction, so circles come out as ovals on a non-square canvas.
  • Trying to remember things between frames. A shader has no state; everything must be computed from position and time.
  • Using step for edges and getting jagged outlines. Use smoothstep across a pixel's width.

Challenge 9

The Shader Sigil

Design an animated emblem, a single symbol that could stand for you, written entirely as one fragment shader. No shapes are drawn: every pixel computes its own colour from distance functions.

Requirements

  • At least three SDF primitives, with at least one that you worked out yourself beyond the circle and box (a ring, a line segment, a triangle, a star).
  • At least two different combining operations, one of which is a smooth union or a subtraction.
  • At least one domain operation: mirroring, rotation, repetition or warping.
  • Colour from a cosine palette whose phases you chose.
  • Animation that loops seamlessly. Drive everything from sin and cos of time multiplied by whole-number multiples of one base speed.
  • All edges anti-aliased with smoothstep.
  • Written by you. Use the examples above as a reference for technique, not as a template to recolour.

Hints

  • Build one shape at a time and view its distance as contour bands (as in example 9.3) until it looks right.
  • For a kaleidoscope, convert to polar coordinates with atan(uv.y, uv.x) and length(uv), fold the angle with mod, then convert back.
  • A ring is abs(sdCircle(p, r)) - thickness.
  • A glow is 0.01 / abs(d), or exp(-k * abs(d)), added to the colour.

Stretch goals

  • Make it respond to u_mouse.
  • Add a fine noise grain so it looks printed, not rendered.
  • Rebuild it in 3D with raymarching.

You are done when

  • A still frame would work as a logo, and the motion has no visible jump when it loops.
  • You can explain what every line contributes to the final colour.
